# ONYX CORE v0.2.0 — Application foundation plan

Tracking: [Issue #5](https://github.com/OnyxJeff/onyx-core/issues/5). Parent release: [v0.1.0](https://github.com/OnyxJeff/onyx-core/releases/tag/v0.1.0). **Status: implemented and field-validated; release audit in progress.**

## Purpose and constraints

Build first authenticated host-to-Pi telemetry path without recreating the complex legacy stack. Original Raspberry Pi Zero Rev 1.3 is **ARMv6**, running 32-bit Raspbian 13 Trixie. Windows 11 SQUALL communicates over already-validated USB RNDIS with ICS. Pi IP is DHCP-assigned and can change; resolve `svr-onyxcore.local`. Do not alter `rpi-usb-gadget`, Windows ICS, or v0.1.0 base network settings.

## V0.2.0 scope

1. Versioned protocol and test fixtures.
2. Small Pi receiver using Python 3 **standard library**, avoiding unverified ARMv6 wheels; bind to the observed USB address only, not `0.0.0.0`.
3. `GET /healthz` and authenticated `POST /api/v1/telemetry`; fixed payload limits, validation, clear status codes, never print credentials.
4. Latest-sample persistence written atomically to a dedicated service data directory. No long-term SQLite history in this release.
5. Windows PowerShell proof-of-concept collector initially using built-in system counters (CPU, memory, uptime). Hardware sensor collection through LibreHardwareMonitor is **an optional follow-up**, not an assumed available API.
6. Secret provisioning and service lifecycle: limited-privilege Pi service account, secure token storage; Windows secure secret storage or protected per-user token, not a token inside a committed task or script.
7. End-to-end tests, graceful reconnect/retry without duplicating collectors, bounded CPU/RAM/disk usage.

## Deferred

Dashboard, charts, alerts, database history, automated backups, companion functions, Wake-on-LAN, remote controls, public internet exposure.

## Implementation checkpoints (completed except release)

1. Review wire protocol, trust boundary and token provisioning; no code deployed.
2. Write protocol fixtures/tests and Pi receiver; run offline/self-contained tests first.
3. Deploy Pi receiver on `svr-onyxcore` only; measure startup and idle RSS/CPU.
4. Write PowerShell collector and verify failure/reconnect behavior, without Windows Scheduled Tasks until manual validation passes.
5. Add systemd service and optional Windows task only after tests.
6. Pi reboot x1, Windows reboot x1, temporary USB disconnect recovery (with appropriate power/data safety), sample freshness, and end-to-end metrics.
7. Audit secrets and release docs; reviewed PR, merge, tag/publish v0.2.0.

## Exit criteria

Core field-validation gates passed, including both system restart paths, USB outage recovery, hidden collector, authentication and snapshot persistence. See [validation evidence](../testing/v0.2.0-validation.md). Outstanding release gates: portability launcher regression and final secret review. Do not claim extended unattended endurance or full production readiness.
