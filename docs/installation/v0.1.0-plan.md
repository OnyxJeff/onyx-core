## Scope
Original Raspberry Pi Zero Rev 1.3 (ARMv6), 32 GB microSD, Raspberry Pi OS Lite 32-bit (Raspbian GNU/Linux 13 Trixie), hostname `svr-onyxcore`, user `onyxpi`; Windows 11 host SQUALL connects via USB data/power cable. No ONYX CORE collector, dashboard, companion, or telemetry services in this milestone.

## Verified operating architecture
- Windows primary Ethernet is the ICS **public** connection, with home LAN address `10.10.10.20`; Raspberry Pi RNDIS adapter `Ethernet 3` is ICS **private**.
- Windows USB interface: `192.168.137.1/24`.
- Raspberry Pi `usb0`: NetworkManager `USB Gadget (client)` via DHCP; observed `192.168.137.167/24` (lease **not guaranteed static**).
- Pi default route: `default via 192.168.137.1 dev usb0`; DNS `192.168.137.1`.
- Normal SSH entry: `ssh onyxpi@svr-onyxcore.local`, validate resolved address and host fingerprint before accepting changes.
- Official `rpi-usb-gadget-ics.service` enabled and active. Its `USB Gadget (shared)` fallback uses `10.12.194.1/28`, **not** the final observed steady-state management path. Do not hard-code a Windows address or substitute a private watchdog.

A diagnostic secondary `10.12.194.5/28` temporarily restored SSH. Pi logs showed repeated client-mode DHCP timeouts and shared/client switching. After ICS client-mode DHCP successfully acquired a lease, the four controlled restart tests above passed. Do not erase the failed test from the incident record.

The Pi's unchanged boot timestamp during the successful Windows reboot shows the Pi did not reboot during that Windows restart.
