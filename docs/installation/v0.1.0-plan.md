# v0.1.0 — USB foundation implementation plan

Tracking: [Issue #1](https://github.com/OnyxJeff/onyx-core/issues/1)  
Branch: `feature/usb-foundation`  
Status: In progress — implementation has **not** been validated.

## Why this milestone comes first

The previous ONYX CORE installation passed service and database checks but became inaccessible when its USB RNDIS link failed to return after a reboot. This milestone gates application development on boot-persistent networking.

## Target hardware and topology

- Raspberry Pi Zero Rev 1.3 (original ARMv6 Zero), 32 GB microSD.
- Windows 11 machine SQUALL; USB data connection also supplies Pi power.
- Planned management IPs: Pi `10.12.194.1/28`; SQUALL `10.12.194.2/28`.
- Optional ICS IPs: Pi `192.168.137.2/24`; SQUALL `192.168.137.1/24`.
- No additional hardware purchases assumed.

## Implementation sequence

1. Preserve the six pre-rebuild verified recovery archives **outside this repository**.
2. Select and record a specific Raspberry Pi OS Lite 32-bit image and its SHA-256.
3. Flash a new card or intentionally overwrite the old one only after confirming recovery copies.
4. Establish local USB gadget enumeration and basic USB management reachability.
5. Establish stable SSH; record host key handling and setup commands.
6. Confirm SQUALL routes the Pi address through the RNDIS adapter.
7. Only then configure and verify ICS if required.
8. Validate reboot persistence: three Pi restarts and one SQUALL restart.
9. Capture actual outputs, troubleshooting instructions, and a tested offline-repair path.
10. Merge reviewed PR, tag `v0.1.0`, and publish GitHub Release.

## Security and recovery requirements

- Never commit API tokens, SSH private keys, passwords, recovery archives, or machine-specific secrets.
- Version configuration templates and sanitized samples, not production credentials.
- Define offline Linux microSD inspection and rollback procedure before declaring release-ready.
- No USB watchdog that repeatedly disconnects the device without explicit testing.

## Public documentation

After technical acceptance, copy a sanitized narrative and evidence summary into the OnyxNet case study in the separate website repository.

## Definition of done

All acceptance items in Issue #1 are checked with actual results. A pull request is reviewed and merged; the GitHub Release is published only after validations pass.
